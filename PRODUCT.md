# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Primary users are not yet finalized. The current product scope is a Nigerian fintech payment gateway serving wallet users and merchants who need to make and manage payments through a mobile-first experience and a desktop dashboard.

## Product Purpose

The product is a portfolio payment-gateway frontend covering a wallet experience, merchant operations dashboard, administrative workflows, payment flows, and a public marketing/documentation surface. Success criteria and the primary user job remain open for future confirmation.

## Positioning

Undecided. The product's differentiating mechanism or market position has not yet been confirmed.

## Operating Context

The product spans mobile-first wallet usage, desktop merchant operations, administrative review, payment links, transactions, withdrawals, webhooks, API keys, team management, settings, and public documentation.

## Capabilities and Constraints

- Implemented as a Next.js App Router web application.
- Current route groups include authentication, dashboard, public documentation, payment, payment-success, and admin workflows.
- The frontend must preserve the project's own brand and fictional demo content rather than copying names, logos, or people from reference material.
- Future design work should use `.github/design/DESIGN.md` as the visual source of truth unless the user explicitly approves a change.
- Additional future constraints and product decisions remain undecided.

## Brand Commitments

- Nigerian fintech context.
- Green brand direction.
- Light Nigerian Pidgin microcopy in in-app UI.
- Plain English for landing-page, error, and security copy.

## Evidence on Hand

- Visual design source of truth: `.github/design/DESIGN.md`.
- Shared component specifications: `.github/design/COMPONENTS.md`.
- Page map and reference mapping: `.github/design/PAGES.md`.
- Local visual references: `.github/design/reference/` (intentionally gitignored).
- Existing frontend implementation under `src/`.

## Product Principles

- Preserve clear, trustworthy payment and account workflows.
- Prioritize mobile usability for wallet tasks and desktop scanability for operations.
- Keep product language locally resonant in the app while using plain English where clarity and security matter most.
- Do not invent product claims, evidence, customers, or future capabilities.

## Accessibility & Inclusion

Future UI work should preserve semantic HTML, labeled icon buttons, visible focus states, and AA contrast as established in the project instructions. Product-specific accessibility needs beyond these requirements remain open.
